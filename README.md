# Aquastone Worktop Studio — конструктор столешниц

Рисование столешницы (детали, мойка, варочная панель, вырезы), раскрой на листы и предварительный расчёт стоимости.

**Демо:** https://ilnard.github.io/aquastone-constructor/ — расчёт выполняется прямо в браузере по демо-ценам, заявки не отправляются.

## Две версии

| | Демо (GitHub Pages) | Рабочий сайт |
|---|---|---|
| Сборка | `VITE_LOCAL_CALC=true npm run build` | `CONSTRUCTOR_BASE=/constructor/ npm run build` |
| Раскрой и цена | в браузере, `src/calc/` (демо-копия цен) | на сервере системы управления, `aquastone-managment/server/calc/pricing.js` |
| Заявки | не отправляются | уходят в раздел «Заявки» системы управления |
| Цены в коде сайта | есть (демо) | нет — `src/calc` вырезается из сборки |

Демо публикуется автоматически при каждом push в `main` (`.github/workflows/pages.yml`).
Файлы `src/calc/nesting.js` и `src/calc/estimate.js` — копии серверных из `aquastone-managment/server/calc/`: при изменении правил раскроя обновляйте оба проекта.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5174 (нужен сервер системы управления)
```

Без сервера, с расчётом в браузере (PowerShell): `$env:VITE_LOCAL_CALC='true'; npm run dev`

## Расчёт — на сервере

Конструктор только рисует эскиз. Раскрой, стыки и ориентир стоимости считает сервер системы управления (`POST /api/calc/estimate`), а допустимые толщины берутся из `GET /api/calc/config`. Цены и коэффициенты (толщина, форма, вырезы) — в `aquastone-managment/server/calc/pricing.js`; после изменения цен пересобирать конструктор не нужно.

Без запущенного сервера системы управления конструктор показывает «Нет связи с сервером расчёта».

На телефоне: одна колонка, крупные кнопки, внизу экрана — панель с ориентиром и кнопкой «Отправить заявку». Детали рисуются и перетаскиваются пальцем.

## Заявки в систему управления

Кнопка **«Отправить заявку на рассмотрение»** отправляет расчёт в систему управления (проект `aquastone-managment`, раздел «Заявки»).

- **Клиент** заполняет ФИО и телефон (с маской `+7 (999) 888-77-66`) и соглашается на обработку персональных данных.
- **Менеджер или директор**, вошедший в систему управления в этом же браузере, формы не видит: в шапке показано, от чьего имени уйдёт заявка, контакты клиента он добавит при создании процесса.

В заявку уходят материал, толщина, декор, форма и все детали и вырезы с размерами и координатами. Площадь, комплект листов, выход материала, стыки и ориентир по стоимости сервер считает заново сам.

### Связь с сервером

Конструктор обращается к `/api` на своём же адресе. При разработке Vite проксирует `/api` на сервер системы управления — адрес задаётся в `.env`:

```
MANAGEMENT_API_URL=http://127.0.0.1:3001
```

Запустите сервер системы управления (`npm run dev:api` в `aquastone-managment`) и конструктор (`npm run dev`). Чтобы менеджер был узнан, откройте оба сайта на одном хосте (например, оба на `localhost`): cookie входа общая для портов одного хоста.

В продакшене опубликуйте конструктор так, чтобы `/api` на его домене вёл на сервер системы управления (например, `location /api { proxy_pass http://127.0.0.1:3001; }` в nginx), а систему управления — на том же домене — cookie входа привязана к домену, иначе менеджер в конструкторе будет считаться клиентом. Готовая настройка nginx и инструкция — `aquastone-managment/DEPLOY.md` (конструктор по адресу `/constructor/`, сборка `CONSTRUCTOR_BASE=/constructor/ npm run build`).
